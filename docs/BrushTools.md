# 브러시 작성 계약

이 기능은 `iiPaintEngine::BrushTools` 선택 구성요소가 소유한다. 소스 호환을 위해
`iiBrushTools` 네임스페이스와 헤더를 유지하며, 설치된 `iiBrushTools::iiBrushTools`
패키지는 같은 구성요소로 연결된다. 기본 `iiPaintEngine` 대상은 작성 계층에
의존하지 않는다. `IIPAINTENGINE_BUILD_BRUSH_TOOLS=OFF`이면 이 구성요소는 설치되지 않는다.
설정 직렬화는 C 로캘의 소수점과 `double` 왕복 정밀도를 사용한다. 숫자 앞의
공백과 `+`, 중복 키와 유효하지 않은 값은 거부하고 기존 설정을 보존한다.
부동소수 `charconv`가 없는 구형 macOS 배포 대상에서도 같은 파일을 읽고 쓴다.

2026-10-27 macOS arm64에서 통합 엔진의 CTest 59/59가 통과했다. 여섯 작성
계약 검사와 새 구성요소·기존 패키지 이름을 함께 사용하는 별도 설치 소비자도
포함된다. Windows·Linux에서 이 통합을 빌드하거나 실행하지는 않았다.
설치 소비자 검사는 성공 시 자신의 임시 설치본과 빌드 결과를 정리하고, 실패 시
진단에 필요한 결과를 보존한다. 앱 실행 검증은 사용자가 요청한 경우에만 수행한다.

iiBrushTools는 전체 획 비율의 Start·End 크기 테이퍼와 사후 보정을 담당하는 상위 작성 계층이다. 입력은 호출자가 소유한 임시 표본이며 함수 호출 중에만 보정한 목록을 만든다. iiPaintEngine의 현재 점 스트리밍과 iiSharedCanvas의 픽셀 문서에 입력 목록·의존성을 추가하지 않는다. 결과는 최종 ARGB 픽셀 타일이다. 문서 커밋·Undo·선택·포인터 캡처·시계는 소비자 책임이다.

## 단위

Size는 문서 픽셀 직경이다. Hardness·Opacity·Flow·Roundness·Spacing·Scatter·Pressure·Tilt·Velocity·Wetness·Mix·Load·Dilution·Start·End·Minimum size·Taper strength는 백분율이다. Angle은 도, Bristle count는 1..64 정수이다. Stabilization은 0..100의 시간 응답, Post correction은 0..20 문서 픽셀의 보정 반경이다.

Start·End는 보정된 전체 길이를 각각 기준으로 한다. 겹치는 테이퍼는 작은 크기를 선택한다. SmoothStep으로 최소 크기에서 기본 크기까지 변화하고, strength는 이 크기 변화의 강도이다. Minimum size는 강도 100%에서의 끝점 직경 비율이며, 다른 강도에서는 기본 크기와 선형 혼합한다. 강도 0 또는 최소 크기 100%이면 크기 축소가 없다. 공간 길이 0인 점은 기본 크기로 남긴다. 기존 엔진의 alpha warmup에 매핑하지 않는다.

Post correction은 호 길이 좌표의 대칭 구간에서 폴리라인의 위치를 적분 평균한다. 양 끝은 고정하고 끝에서 가까우면 반경을 줄인다. 시간·압력·기울기·회전·custom 값은 보존한다. 현재 당김줄 반경과 별개이다. 큰 좌표의 누적 모멘트 차감 오차를 피하기 위해 길이와 중심을 가진 범위 트리를 사용하며, 각 보정점은 O(log n)으로 조회한다.

Stabilization은 사후 보정 전에 내부 점에 적용하는 인과적 시간 필터이다. 시간 상수는 `0.25 × (값/100)²`초이며 가중치는 `1−exp(−경과시간/시간상수)`이다. 처음과 끝은 실제 입력 위치로 고정한다. 0이면 필터를 생략하고 같은 시각의 내부 표본은 이전 필터 위치를 유지한다. 이 전체 작성 렌더의 끝점 정책은 하위 엔진의 스트리밍 당김줄 정책과 별개이다.

## 도구별 효력

Wetness·Mix·Load·Dilution은 Mixer·Smudge에서, Bristle count는 Bristle에서만 활성이다. Airbrush는 초당 30회로 배치하므로 공간 Spacing을 비활성으로 보고한다. Start·End가 모두 0이면 Minimum size·Taper strength를 비활성으로 보고한다. 비활성 값도 설정에 보존하지만 픽셀에 영향을 주지 않는다.

Pressure는 크기와 dab 유량, Tilt는 타원의 변형에 적용한다. Velocity는 실제 속도를 기준 속도로 정규화한 뒤 불투명도를 줄인다. 기준은 `DynamicsContext::velocityReferenceSpeed`의 기본값 1200 문서 px/s이며 호출자가 바꿀 수 있다. 배율은 `1−(Velocity/100)×clamp(속도/기준속도,0,1)`이다. 10% 설정은 속도가 커져도 최대 10%만 줄인다. 원시 속도에 백분율을 직접 곱하지 않는다.

Dilution은 pickup=v, deposit=1−v이다. Load는 각 자국의 물감 기여율이며 지속적인 물감 잔량이 아니다. Bristle count는 실제 생성한 비트맵 팁의 모 개수를 바꾼다. Roundness 0%는 최종 배치의 짧은 축을 1 문서 픽셀로 만든다.

Eraser의 커버리지는 Opacity·Flow·압력으로 정하고 전경색의 alpha에 의존하지 않는다. Spacing 0%는 무한 배치가 아닌 엔진의 양수 최소 간격으로 연속 자국을 근사한다. 기본 density에서는 직경의 0.1%와 0.01 문서 px 중 큰 값을 하한으로 사용하며, 배치 예산도 적용한다.

## 경계와 수명

입력과 시각은 유한하고 시각이 역행해서는 안 된다. 입력·dab·투영 면적·건드린 타일의 예산을 검사한다. 거부된 렌더는 부분 타일을 반환하거나 호출자의 소스·입력을 변경하지 않는다. 시스템 메모리 고갈의 무실패를 보장하지 않는다.

소스 샘플러는 획 시작 픽셀을 동기적으로 읽는다. 콜백의 컨텍스트는 호출이 끝날 때까지 유효해야 하며 범위 밖은 투명하다. 콜백이 없으면 투명 소스이며, 콜백을 제공하면 너비·높이가 양수여야 한다. 결과 타일은 64px 격자에서 clip으로 자른 사각형이며 로컬 픽셀을 소유한다. 같은 획의 누적 alpha는 부동소수로 유지하고 마지막에 원본과 합성한다. 타일 전체를 한 문서 명령으로 커밋할 책임은 소비자에게 있다.

새 입력이 추가되면 전체 길이와 사후 보정 결과가 바뀌므로, 작성 미리보기는 이전 결과를 교체해야 한다. 이미 합성한 미리보기 위에 새 결과를 덧칠해서는 안 된다. 종료와 동일한 입력을 렌더하면 동일한 픽셀이다. 문서·설정 직렬화에 원시 입력을 저장하지 않는다.

## 수락 검사

각 22개 파라미터를 유효한 도구·입력에서 단독으로 바꿔 픽셀 차이를 검사한다. Start·End는 중심 alpha와 실제 단면 폭을 함께 검사한다. 사후 보정은 끝점·센서 값·변위 한도·기존 대응점의 평균에 대한 직선 구간 분할 불변성을 검사한다. 별도 설치 소비자도 같은 공개 계약을 실행한다. 이 검사는 앱 채택이나 물리 펜·다른 플랫폼 실행을 의미하지 않는다.


## 기본 프리셋과 미리보기 대기열

`resolveWithPreset`과 `renderGestureWithPreset`은 호출자가 제공한 기본 프리셋을 복사해
22개 작성 컨트롤을 적용한다. 대칭, 절대 간격, 압력 응답과 별도의 alpha warmup 등
다른 지원 설정은 유지하고 입력 프리셋은 바꾸지 않는다. 작성 계층의 위치 보정과
스트리밍 smoothing이 중복되지 않도록 후자는 사용하지 않는다. 현재 타일 합성은
SourceOver와 지우기만 지원하므로 다른 blend는 거부한다. Bristle은 개수에 따른 팁을
생성하며 사용자 지정 Bristle 팁이나 팁 시퀀스는 조용히 무시하지 않고 거부한다.
`availabilityWithPreset`은 알려진 플래그와 절대 간격 우선순위가 컨트롤을 가리는
경우를 보고하지만 프리셋 전체 검증이나 모든 입력에서 픽셀 변화가 난다는 보장은 아니다.

`PreviewQueue`는 입력 표본을 상한 내에서 보존하며 한 번에 하나의 작업만 발행한다.
오래된 결과, 취소된 획의 결과와 실패를 구분하고 최신 획 종료는 결과 적용 뒤에
확정할 수 있다. 모든 대기열 호출과 적용 판단은 같은 소유 실행 영역에서 직렬화한다.
작업자는 대기열이 복사한 표본을 소유하지만 렌더링, 불변 원본 픽셀 스냅샷,
워커 수명, 문서 커밋과 적용 실패 시 취소는 호출자의 책임이다. 대기열 자체는
문서를 스레드 안전하게 만들거나 프로세스 전체 메모리를 제한하지 않는다.
이 API를 사용하는 앱은 렌더링과 문서 커밋 경계를 별도로 구현하고 검증해야 한다.


## 불변 원본 타일과 렌더

`FrozenSourceBuilder`는 소유 실행 영역에서 요청한 64×64 원본 타일만 복사한다.
각 추가 작업은 필요한 타일을 임시로 수집하고 모든 읽기가 성공한 뒤 게시한다.
이미 수집한 타일은 재사용하며, 예산 초과·읽기 실패·콜백 예외는 기존 수집 상태를
보존한다. 콜백 중 중첩 수집·스냅샷 생성은 거부한다. 콜백은 수집기를 이동하거나
파괴하지 않아야 한다. 수집기는 스레드 안전하지 않고, 모든 타일이 같은 획 시작
리비전에서 왔는지 확인하는 책임은 호출자에게 있다.

`freeze`는 타일 인덱스를 복사하고 불변 픽셀 타일을 공유한다. 이전 스냅샷은
이후 수집이나 수집기 수명과 독립적이다. 소스 영역 밖은 투명이며 영역 안의
미수집 타일은 누락으로 식별한다. 작업마다 별도의 `FrozenSourceSampler`를
사용하고 `complete()`가 거짓인 결과는 폐기해야 한다. `renderFrozenGesture`는
이 검사를 자동으로 수행해 누락된 원본을 읽은 렌더 전체를 오류로 거부한다.
`renderFrozenGestureWithPreset`은 같은 누락·오류 계약을 사용하면서 지원되는 기본
프리셋의 절대 간격·대칭·사용자 팁 등을 작성 컨트롤과 함께 적용한다. 입력 프리셋은
변경하지 않으며 지원하지 않는 설정은 `BrushFailure`로 원래 작성 오류를 보존한다.
선언한 소스 경계 밖은 투명이므로 실제 픽셀이 있을 수 있는 범위를 경계에 포함해야
한다. 수집할 타일의 작은 영역을 전체 소스 경계로 잘못 지정하면 누락 오류 없이
잘못된 투명값이 생길 수 있다. 청크·무한 소스는 안전한 좌표 범위를 선택하거나
그 밖이 비어 있음을 호출자가 확인해야 한다.

타일 제한과 논리 바이트 수는 픽셀 저장량을 나타내며 인덱스, 공유 포인터, 임시
수집량과 할당자 오버헤드는 별도다. 획의 전체 원본 샘플 범위 계획, 리비전 고정,
작업자 스케줄링·취소, 문서 커밋과 앱 채택은 호출자가 담당한다. 희소 8K 범위
좌표를 이용한 단위 검사는 실제 8K 파일이나 장치 실행의 증거가 아니다.

공개 헤더는 직접 사용하는 표준 선언을 명시적으로 포함해 간접 포함에 의존하지 않는다.


### 누락 타일 탐색

`renderFrozenGesture`가 수집되지 않은 원본을 읽으면 결과는 폐기되고 오류에
요청된 64×64 정렬 타일 목록이 행·열 순서로 포함된다. 소유 실행 영역은 같은 획
시작 리비전의 원본에서 이 타일을 수집하고 새 스냅샷으로 다시 렌더할 수 있다.
원본에 따라 추가 타일을 요구할 수 있으므로 호출자는 재시도 횟수와 전체 타일
예산을 제한한다. 누락 보고가 지정 개수를 초과하거나 메모리를 확보하지 못하면
각각 명시적 오류를 반환하고 부분 보고를 완전한 목록으로 취급하지 않는다.

스냅샷은 여러 작업이 공유할 수 있지만 각 작업은 별도의 샘플러를 한 작업자에서
사용하고, 렌더가 끝난 뒤에만 누락 보고를 읽는다. 바깥 경계는 전체 유효 원본
범위를 포함해야 한다. 합성 8192×8192 좌표의 대각선 획은 382개 타일의
논리 픽셀 6,258,688바이트로 원본 전체를 제공한 렌더와 일치했다. 인덱스,
렌더 버퍼, 할당자 오버헤드는 포함하지 않았으며 실제 8K 파일이나 앱 성능
수락의 증거는 아니다.
